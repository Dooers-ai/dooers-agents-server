# Maestro usage: opt-in local candidate

`dooers.agents.server.maestro.usage` builds on the authoritative `PostgresEffectJournal` and its shared private SQL backend. Operators explicitly provision `JournalUsage` once after verifying the existing generation/inventory; runtime code never creates a replacement empty journal. No default runtime, legacy provider or gateway is changed or activated.

A trusted workflow calls `run_maestro_usage` inside its existing `JournalExecution`/`bind_effects` scope. Configure `LocalFinancialClient` with the exact local Core sandbox endpoint and a separate current financial credential resolver. Pass a trusted `MaestroEffectTool` whose `execute(arguments, provider_operation_id, decision_id)` returns `(PrivateEffectResult, measurement)`. Measurement has exactly `provider_request_ref`, `measurement`, `provider_outcome`, `units`, `reasoning_tokens`, `prompt_tokens_total`; E10-01 units are closed and quantities are canonical strings. Never pass prompts, results, bearer tokens, raw URLs or credentials in a usage fact.

For several real calls within one effect, keep `ordinal` and validated workflow arguments stable. First call: `operation_slot=0`, `reason='initial'`, `final_effect=False`. It returns `UsageResult(provider_operation_id, value)`. Next deliberate call: slot 1, parent equal to the first UUID, reason `new_step`/`fallback`/`retry_real`, and `final_effect=True` when the workflow closes. Each real operation gets its own immutable fact. Retrying the same slot reuses its UUID/result after current authorization; it never adds cost. Slots are semantic plan positions, not transport attempt counts. Changed intent/configuration conflicts, an uncertain operation is not permission to rerun, and a missing slot is not a duplicate of a completed effect.

The UUID is persisted before network; Core authorize/reserve/start and current Maestro authority are required before provider cost. Operation close, usage fact, report intent and effect revision commit together in the SAME authoritative private transaction. Network is outside SQL. Private result/receipt never enters the fact. A kill before this commit leaves a started operation observable; a trusted operational reconciler may account verified durable provider evidence at the expected revision after cancellation, without invoking provider, renewing lease or publishing output. Unknown finalized usage is immutable and requires a separately defined correction policy; it is never overwritten or converted to zero.

`JournalUsage.pending/health` and `retransmit_usage(..., LocalUsageSink(...), limit=10)` expose bounded replay of sanitized facts to the Maestro durable inbox. Use another bearer resolver for that inbox, separate from financial/journal/dispatch credentials. ACK includes exact usage identity/hash only after inbox commit; Core receipt is a later, distinct confirmation. Rotation preserves the original identity/hash/binding. Failed transmission leaves the original durable intent pending; it does not repeat provider or erase committed output.

After a callback-authenticated canonical output receipt, `record_output_receipt(operation, receipt)` appends an ID-only link in the same journal backend. `retransmit_usage` sends these links after facts within the total batch limit. Maestro verifies canonical output, original author and delivery/phase/namespace; links never mutate the fact hash.

This candidate supports the synthetic local E10-07 Core policy only. There is no paid provider, production billing policy, gateway authority bridge, package publication or activated deployment. Canonical form submit/resume integration remains E11-03/04; controlled journal phase fixtures do not claim that journey is complete.
